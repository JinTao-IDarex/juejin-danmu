# Design Spec · 掘金弹幕 Logo 优化（三方向共同输入，唯一输入）

## 任务本质（顾问式重述）
用户要的不是"换个新 logo"，而是**把现有 logo 做一次专业化升级**：保留品牌记忆（掘金蓝底 + 白色弹幕条 + 黄点），修正它的构图、语义和小尺寸表现问题。这个图标会出现在两个地方：Chrome 商店页（大尺寸，要精致、有品牌感）和浏览器工具栏（16px，要一眼认出）。受众是掘金的技术开发者——他们对"粗糙的 AI 感"极度敏感，对"克制的几何 + 一点巧思"极度欣赏。情感基调：**专业里带一点弹幕文化特有的俏皮**（不是企业感，也不是幼儿向卡通）。

## 交付物（每方向一份，硬规格）
一个**自包含单文件 HTML**（无外部依赖、无网络字体），文件名 `direction-X.html`，内容包含：
1. **Hero 区**：logo 主体以 inline SVG 呈现，≥480px 展示，1:1 画布
2. **真实尺寸墙**：同一 SVG 以 16 / 24 / 32 / 48 / 128px 真实渲染（浏览器缩放禁用，用 width/height 属性原尺寸渲染）
3. **背景适配行**：白色背景、深色（#1B1F27）背景、掘金蓝页面背景三种环境下各放一个 96px 实例
4. **一句话设计诠释** + **form 来源说明**（这个形是从产品的哪个特征长出来的）
5. 页面本身排版干净即可（中性灰白底），不要把预览页做成海报

## 技术硬约束（三版统一）
- Logo 全部用 **inline SVG**（`viewBox="0 0 512 512"`），几何图形 = rect(circle/path + 圆角)，允许用 `<defs>` 渐变但仅限蓝色系深浅，禁止装饰性渐变
- 底板：**大圆角方形**（圆角半径约为边长 22-24%，对齐 macOS/Chrome 现代图标体系）
- 三版必须同尺寸同画布规格，仅设计诠释不同
- 16px 可辨认是硬底线：主体元素在 512 画布上投影到 16px 后仍 ≥2px 视觉宽度（即 512 画布上 ≥64px）
- 弹幕条保留"长短参差"的节奏（3 条不同长度），黄点保留但**必须与弹幕条发生关系**（不再是游离的点）

## 三方向的设计诠释空间（互异要求）
三版**布局骨架必须互异**：弹幕条的排布逻辑、黄点的角色、底板处理至少一项结构性不同。以下为各方向的生成逻辑：

- **Direction 1（秒数轮盘 · 风格 #7）**：读 `C:\Users\apple\.agents\skills\huashu-design\references\design-styles.md` 网页分区 **#7** 的风格 DNA，把该风格的视觉语言**翻译成 logo 语言**（不是做网页，是让标志带有该风格的气质）。若该风格含不适用于 16px 的元素（纹理/噪点），用纯色几何降级。
- **Direction 2（现实参照 · 标杆迁移）**：用 WebSearch 核实 **Bilibili 客户端图标**与 **iMessage/Google Messages 气泡类图标**的设计语言（为什么好：几何极简、单一母题、小尺寸极稳），拆解其构成逻辑后**迁移**到掘金弹幕的品牌 DNA 上——学的是"气泡轮廓承载内容条"的结构思路，造型必须原创，禁止描摹 B 站电视机。
- **Direction 3（最佳设计师 · 负空间叙事）**：启用 **Pentagram 级几何标志思维**（参考 Mackey Saturday 的负空间手法：字母/符号藏在图形负空间里）。在"弹幕条与黄点"的关系里藏一个语义彩蛋——例如黄点即句号、弹幕条排列暗合"掘"字笔画或 J 字母、或黄点是气泡的尾巴起点。 reduction 到极致：整个标志 ≤4 个几何元素。

## 已知假设（用户未逐条确认，按 best judgment 补齐）
- 保留现有品牌基因做"优化升级"，不是推翻重来
- 主色统一回归掘金官方蓝 #1E80FF（现用图标的蓝偏浅，属历史偏差）
- 底板改圆角是符合 Chrome/macOS 现代图标体系的行业默认
